# AI Engineer Portfolio Constitution

**Version:** 0.1.0-draft | **Prepared:** 2026-10-01 | **Ratification:** pending owner sign-off

## Core Principles

### I. Source fidelity and explicit decisions
The complete North Star export controls narrative intent; the CV controls professional claims. Newer explicit owner decisions take precedence. Preserve source assets. Never invent awards, results, publications, destinations or approved artwork. Proposals remain draft until approved.

### II. A persistent, visitor-controlled world
After the cinematic intro, visitor progress is the only authority for journey transformations. Backward input reconstructs earlier compositions deterministically. Navigation expansion changes UI state only; selecting a stage traverses the same journey. No disconnected page sections, unrelated animation resets or automatic journey progression.

### III. Measured spatial ambition
Next.js App Router, TypeScript, Tailwind CSS, GSAP and ScrollTrigger are selected. Spatial WebGL and particle systems are permitted and encouraged when meaningful. Measure the 60 FPS target on declared representative hardware; reduce cost before changing the approved composition. No heavy client ML for detection, no gratuitous second animation engine or frame-by-frame React rendering.

### IV. Accessible content, independent of effects
Semantic content and controls must remain readable without JavaScript/WebGL. Provide keyboard/touch interaction and a reduced-motion path. English first; localized content, text direction and layout are independent of motion geometry. Face-detection graphics are illustrative, never biometric measurement claims.

### V. Editable content without choreography edits
Versioned, validated content contracts separate profile/copy/media/links from stage identifiers and motion. Reject invalid URLs, unsafe markup, unknown fields and out-of-bounds media anchors. Content changes may not alter the timeline or execute code. A future authenticated admin is required; its vendor is not selected now.

## Additional Constraints

- Install tools/cache inside the project; no global PATH, Hermes profile/skill or unrelated configuration changes.
- No source photo background service upload, remote repository, deployment, paid service or public publication without authorization.
- Preserve source originals and verify SHA-256 against the baseline.
- Modern desktop/tablet/phone layouts; content is not trapped behind cinematic loading.
- Ponytail full: the minimum justified architecture; do not generate services or abstractions for speculative needs.

## Review Workflow

Main baseline docs/assets were explicitly authorized. Milestone 1 changes stay on `feature/spec-kit-setup`. Milestones 2 and 3 have distinct branches; subsequent components remain separately gated. Documentation/contract checks and visual review precede sign-off. Application implementation and all merges require explicit owner approval. A documentation commit is not an approval.

## Governance

Amendments record the affected requirement, reason and owner decision before implementation. Original Spec Kit templates remain upstream scaffolding; authored feature docs contain no template placeholders. Draft plan/tasks are provided together because the owner explicitly requested a roadmap, but neither is authorization to implement. Outstanding downstream provider choices gate their own milestone, not this spec package.
