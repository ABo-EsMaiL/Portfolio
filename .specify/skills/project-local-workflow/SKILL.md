# Project-local setup and verification

This skill is deliberately stored in the repository, not registered in a global Hermes profile. Read AGENTS.md, tasks/todo.md and the active spec before acting. Latest explicit owner authorization controls scope.

- Check Git status/branch before changes. Scope every milestone to its authorized feature branch. Commit tested slices only when explicitly authorized; merge only after explicit owner approval. Local tags are allowed only for authorized milestone checkpoints. Never push or add a remote without authorization.
- Preserve the three source assets and verify their pinned SHA-256 values in docs/tooling-lock.json. The original North Star mixes LF/CRLF; its -text attribute preserves raw bytes. Historical main's first blob normalized newlines, so compare documented raw and baseline hashes separately; never rewrite the original to make a check pass.
- Keep developer environments/models/caches in .tools; temporary work in project tmp/. Set UV_CACHE_DIR, U2NET_HOME, TMP/TEMP and npm cache explicitly before tool work. App node_modules/.next remain local and ignored. Native Spec Kit Hermes integration writes globally: retain generic .specify/commands instead.
- Select Spec Kit's tracked feature explicitly with SPECIFY_FEATURE=001-cinematic-identity. Active-feature state is intentionally Git-ignored.
- Discover real package engines/peer ranges before pinning; latest is not compatibility proof. Keep package-lock.json. Do not force peer overrides or skip validation to silence incompatibility. Record named tooling support gaps and production audit results.
- Prefer installed Edge and a project-local browser profile for tests; do not download a duplicate browser by default. Verify a server with a real HTTP health check, not a blind wait. Stop only browser processes belonging to this review.
- Run npm run test:unit, npm run typecheck, npm run lint, npm run build and phase-appropriate contract/source checks. Never call passing lint or document screenshots proof of a working Hero, matte quality or 60 FPS.
- Render actual implementation at required widths and inspect screenshots. Test keyboard, reduced motion, no JS/WebGL, repeated interruption and lifecycle teardown. Record actual traces/build/device details; missing real phone access remains an explicit approval gap.
- Prioritize art-direction review before extended performance investigation when the rendered treatment is unaccepted. Functional checks do not substitute for composition, atmospheric depth, visible silhouette effects or glass detailing; obey an owner's explicit pause on benchmarks.
- Inspect annotation text at 320px independently of document overflow: a fixed percentage badge can keep the page in bounds while its text escapes the glass. Give the badge a content-safe minimum width and check its vector still begins at the authored face anchor.
- Source portrait processing is offline and owner-authorized. Models must stay out of public/ and client imports. Preserve natural facial pixels; inspect matte edges on dark/light/checkerboard at full resolution.
- Do not run full-resolution closed-form matting concurrently with builds/browser profiling: peak allocation can exhaust virtual memory. Re-export from a hash-verified reviewed matte explicitly; never silently switch to a poorer mask or call reuse a successful inference rerun.
- Release the completed ONNX Runtime session before allocating full-resolution matting's sparse system. The inference arena otherwise overlaps a multi-gigabyte solver; retain solver/resolution and compare every export/manifest hash after a full rerun, rather than silently changing matte quality.
- Rebuild before production review and verify a current markup marker over HTTP after restarting: an old Next server can retain previous build state. If managed stop fails, verify the listening PID's exact project command before terminating it; use the discovered native PowerShell executable path rather than changing PATH.
- Test input before image decode as well as during each intro phase: late assets must never restart an already resolving/ready intro. Keep physical input/device traces distinct from synthetic event-handler tests.
- Do not edit global profile/skills/PATH or source originals. Do not clean shared caches without permission. Record boundary incidents honestly.
- Require actual WebGL=true, renderer calls/counts and shader-error-free captures; a browser suite that accepts DOM fallback does not verify spatial integration. Force context loss and check actual draw calls stop as the cutout returns.
- Keep native input, synthetic phase events and simulated visibility explicitly labelled. Automation may keep document.hidden false despite tab/window switching; do not claim a native visibility pass from an injected property. Preserve failed native-probe evidence and leave a manual gate.
- Report both RAF cadence and compositor trace frames. Preserve discrepancies and cold shader stalls; a low own CPU+GPU cost does not certify panel FPS. Capture verbose and lightweight trace baselines separately; do not call a smaller capture an app optimization.
- Probe KHR_parallel_shader_compile before diagnosing cold WebGL stalls. Use the installed renderer's compileAsync before first render while keeping the DOM image visible; guard disposal/host disconnect after awaiting. Measure before/after and disclose uncontrolled driver-cache variance rather than guaranteeing stall elimination.
- Keep native wheel/touch over a capsule distinct from hover/toggle state. Wheel is journey intent; Space on a button activates UI. Gate touch hover protection with the actual fine-pointer media query, not matches(':hover') alone.
- Preserve explicit capsule toggles while focus remains inside navigation; pointer re-entry caused by a shrinking control must not expand it immediately before the next click. Animate the glass clip and child transforms, not world progress or text scale.
- Register short-phase tests at DOMContentLoaded or capture phase mutations before hydration; waiting for all resources can miss the entrance phase after shortening an intro. Keep the real user timing, not longer choreography just to satisfy polling.
- When an owner supplies a hero moodboard, inspect its pixels and separate atmosphere/material from baked marketing copy and generated identity. Build the scene from the source portrait and CV; identify illustrative vector data as synthetic rather than implying client inference.
- Keep relocated trackers outside the portrait frame and assert rectangle non-overlap at responsive sizes. If an auto-width capsule replaces a fixed backing, avoid delayed `display` transitions: outgoing content plus the newly visible collapsed label can briefly enlarge the pill instead of shrinking it.
- After structural design rejection, stop recoloring the rejected layout. Verify a separate composition study against the owner's actual identity and seek visual acceptance before integrating it; preserve the production motion/fallback contracts until replacement is approved.
- When switching Next dev/production modes, do not include both generated route/cache-life declarations from stale output. Stop only the owned dev listener and remove ignored `.next/dev` output before rebuilding production; let Next regenerate `next-env.d.ts` rather than editing it or weakening type checks.
- When checking dev after a production review, remove only inactive ignored `.next/types` declarations before starting/checking dev, not active dev cache or build assets; overlapping global generated declarations otherwise produce false duplicate-type errors.
- Keep Playwright video support local: install only FFmpeg with `PLAYWRIGHT_BROWSERS_PATH` set to `.tools/playwright`, retain the installed Edge channel, and use that same variable when recording. No global browser cache or duplicate browser download is required.
- Verify mobile moving packets against the start of About copy, not just document overflow. Keep complete pre-existing cables extending beyond the reviewed scene, and restrict packet visibility near readable copy rather than extruding or shortening the wires. Preserve independent binary inputs and CV-backed domains.
- Fade a persistent page h1 with opacity, not visibility, when its visual treatment leaves a spatial stage; retain semantic heading access and run Axe at both journey endpoints.
- Check short viewport heights as well as widths. Keep enough stage/track extent for the complete CV copy to be reached via native scroll rather than hiding it inside a clipped viewport or shrinking type further.
